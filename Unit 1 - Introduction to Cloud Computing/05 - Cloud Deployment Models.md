# Cloud Deployment Models

## 1. Definition

A Cloud Deployment Model describes how cloud infrastructure is deployed, who owns it, and who can access it.

According to the class notes, there are four cloud deployment models.

## 2. Public Cloud

### Definition

A Public Cloud provides cloud services over the internet for use by customers. The infrastructure is managed by a cloud provider.

### Characteristics

- Available to multiple customers.
    
- Accessed through the internet.
    
- Resources can be scaled according to demand.
    
- Usually follows a pay-as-you-use model.
    

### Advantages

- Low initial investment.
    
- Easy scalability.
    
- No need to maintain physical servers.
    
- Suitable for many types of users.
    

### Disadvantages

- Depends on internet connectivity.
    
- Security and privacy need careful management.
    

### Examples

- Amazon Web Services (AWS)
    
- Microsoft Azure
    
- Google Cloud Platform (GCP)
    

### Real-Life Example

A student uses Google Drive to store assignments online.

## 3. Private Cloud

### Definition

A Private Cloud is cloud infrastructure dedicated to a single organization. It may be managed by the organization or a third-party provider.

### Characteristics

- Used by one organization.
    
- Greater control over resources.
    
- Can be located on-premises or hosted externally.
    
- Suitable for sensitive data.
    

### Advantages

- High security.
    
- Better control.
    
- Customization according to organizational needs.
    

### Disadvantages

- Expensive to build and maintain.
    
- Requires skilled IT staff.
    
- May have limited scalability compared with a public cloud.
    

### Examples

- A bank's private cloud.
    
- A university's private cloud.
    

### Real-Life Example

A bank stores customer financial data in its own private cloud.

## 4. Hybrid Cloud

### Definition

A Hybrid Cloud combines public and private clouds, allowing data and applications to move between them.

### Characteristics

- Combines public and private clouds.
    
- Supports flexible workload management.
    
- Offers better scalability.
    
- Sensitive information can remain in a private environment.
    

### Advantages

- Cost-effective.
    
- Flexible.
    
- Supports disaster recovery.
    
- Sensitive data can remain private.
    

### Disadvantages

- More complex to manage.
    
- Integration can be challenging.
    
- Requires strong security policies.
    

### Examples

- Hospitals.
    
- E-commerce companies.
    
- Government organizations.
    

### Real-Life Example

An online shopping website keeps sensitive payment data in a private cloud while hosting its website on a public cloud.

## 5. Community Cloud

### Definition

A Community Cloud is shared by multiple organizations with similar requirements, such as security, compliance, or regulations.

### Characteristics

- Shared by organizations with common goals.
    
- Costs are shared.
    
- Managed jointly or by a third party.
    
- Designed around common requirements.
    

### Advantages

- Cost sharing.
    
- Better collaboration.
    
- Improved security for shared requirements.
    
- Supports industry-specific regulations.
    

### Disadvantages

- Limited flexibility.
    
- Shared resources.
    
- Requires coordination among members.
    

### Examples

- Government departments.
    
- Healthcare organizations.
    
- Universities sharing research infrastructure.
    

### Real-Life Example

Several universities share a cloud platform for research projects and educational resources.

## 6. Quick Comparison

|Model|Who uses it?|Main feature|
|---|---|---|
|Public Cloud|Multiple customers|Shared provider infrastructure|
|Private Cloud|One organization|Dedicated infrastructure|
|Hybrid Cloud|An organization using both public and private clouds|Combines the two environments|
|Community Cloud|Organizations with common requirements|Shared infrastructure for a community|
